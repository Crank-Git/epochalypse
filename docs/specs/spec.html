epochalypse

Overview

epochalypse provides time capsules, renewable dead man’s switches, and DNS countdowns. Developers use a Go CLI and a resolver lab. Individuals use an owner dashboard and public release pages. The project supports local containers and Linux VPS hosts.

DNSSEC signature windows demonstrate validator behavior. They do not keep published data secret. Encrypted capsules use server-held keys or a verified drand beacon. Independent agents support switch release after the main server fails.

The owner states: “outage shouldnt stop this as it undermines the entire deadman switch behavior.” The accepted direction covers main-server loss plus one unavailable agent by Bmax plus the reviewed allowance E. After incomplete receipts, the client reports uncertainty from B0 through Bmax. B0 is the earliest possible disclosure boundary. Three durable receipts confirm renewal. No replacement protocol has production acceptance. See ADR 0012 and the direction report. A separate research epic assesses loss of all project-operated servers.

Goals

  • Provide all three variants through a CLI and web pages.
  • Demonstrate future-signature behavior through real validating resolvers.
  • Distinguish validation, confidentiality, and availability in every release mode.
  • Recover switch content after main-server loss plus one agent outage.
  • Pass every required test before merge.
  • Maintain at least 95.00 percent aggregate statement coverage for first-party Go code.
  • Record a reproducible total-loss research result.

Non-goals

V1 excludes multiple owner accounts, billing, and a managed hosted service. Future work includes multiple accounts with separate dashboards. V1 excludes exact-time acceptance by arbitrary resolvers and secrecy from public RRSIG windows. V1 does not guarantee switch recovery after every agent disappears. V1 does not claim resistance to collusion by two agents or a compromised preparation client.

Architecture & stack

flowchart LR
 Owner[Owner CLI or browser] --> Main[Main Go server]

 Resolver --> Visitor[Visitor]
 Main --> Store[Durable local state and ciphertext]
 Main -->|Initial replication| Agents
 Visitor -->|Recovery bundle| Agents
 Visitor --> Beacon[Verified drand beacon]
 Agents -->|Two release shares and ciphertext| Visitor

Use Go 1.27.3 with standard HTTP, templates, JSON, and CLI flags. The Go release history documents this version and its security fixes. Use server-rendered HTML with a small local JavaScript layer. The web interface requires no external frontend service. Use cmd/epochalypse for the executable and internal/ for domain modules. Separate modules cover authentication, DNS, capsules, switches, agent state, content, and the clock. Use injected clocks for deterministic tests. Use monotonic durations for local scheduling, with explicit UTC release boundaries.

Use codeberg.org/miekg/dns v0.6.128 for the authoritative server and DNS clients. Keep miekg/dns v1.1.73 as an isolated comparison dependency. The compatibility report records real resolver evidence and API limits. ADR 0004 records the choice. The implemented contracts are in docs/windows.md and docs/observations.md. The tlock v1.2.0 compatibility report verifies an explicit quicknet identity. Use docs/research/tlock-compatibility.md before production integration; example defaults have no authority. Owner state uses bbolt v1.5.0 and Argon2id from golang.org/x/crypto v0.58.0. ADR 0003 and docs/owner.md define the verified storage and password contracts. The foundation pins the lint tools in its check scripts. The threshold library remains gated on protocol acceptance; no interface has approval.

Use provider-neutral Linux services and container examples. Managed platforms must meet port and state requirements. Each agent provides its own public recovery endpoint and durable ciphertext copy. The main server is absent from the switch recovery path.

Cross-cutting concerns

Authenticate mutations. Authorize each token scope. Sign direct check-ins with an owner key. Use TLS outside the isolated local lab. Require anti-replay checks on agent messages. Use generic authentication errors and specific validation errors. The API error shape is {error:{code,message,fields,request_id}}. Use 400 for malformed input, 401 for missing authentication, and 403 for insufficient scope. Use 404 for absent public objects, 409 for state conflicts, 413 for size limits, and 429 for rate limits. Use 503 for an unavailable dependency. Use 425 for a server-held key before release. Use request IDs across logs. Exclude plaintext, passwords, tokens, private keys, and key shares from logs. Bound request time, memory, disk quotas, and concurrent work. Default to 100 retained objects and 1 GiB per installation. The owner can change storage quotas. Failed quota checks leave no armed switch.

Use keyboard-accessible controls, semantic labels, visible focus, and textual state labels. Support responsive light and dark layouts. Use English copy in v1. Show UTC with a local-time display. Never derive release authority from a visitor's browser clock. Target a local p95 below 250 ms for metadata reads at 20 requests per second on a two-core host. Exclude uploads and cryptographic preparation from that latency target. Record the benchmark host and workload. Treat this target as a benchmark gate before release, not a claim about arbitrary VPS hosts.

Configuration holds the zone name, agent endpoints, failure domains, public keys, beacon chain, and protocol version. Configure distinct subdomains and signing-key references for signature-window experiments and countdowns. Testing strategy

Required pass rate is 100 percent. Coverage is a separate minimum of 95.00 percent. Measure Go statement coverage across every first-party production package, including CLI and HTTP adapters. Exclude dependencies and generated third-party code. Do not exclude difficult branches to reach the threshold. Fail the coverage check when the profile is absent, empty, malformed, or below the unrounded threshold. Require explicit tests for every security and deadline boundary regardless of coverage.

Use TDD for behavior changes. First demonstrate a failing assertion against the existing behavior. Then implement the smallest change that passes. Refactor while the checks remain green. A new test that fails only because of a syntax error does not demonstrate the behavior. Record the fail/pass commands in the PR description without mandatory changelog edits.

Unit tests cover validation, authorization, TTL arithmetic, round selection, and state transitions. Integration tests cover durable receipts, restarts, uploads, replication, and verified decryption. E2E tests cover owner setup, sign-in, creation, publication, check-in, and independent recovery. Test empty, active, unavailable, released, invalid, and unauthorized states. Resolver tests cover trust chains, CD, direct queries, skew, bogus caches, expiry, truncation, and TCP. Test clocks before, at, and after each boundary. Test backward and forward clock changes. Test partial renewal, late renewal, lost replies, stale backups, repeated requests, and parallel check-ins. Test corrupted ciphertext, signatures, shares, and beacon responses without partial plaintext output. Stop the main server and one agent before the switch boundary. Recover through the remaining agents. Live public beacon probes remain optional diagnostics. Deterministic verified fixtures gate CI. Separate scheduled extended fuzz and fault runs from required short PR checks. A skipped required test fails CI. Retries cannot turn a flaky first failure into a passing required result without diagnosis.

Assumptions

Use epochalypse as the project name. Use the owner's personal GitHub repository when one exists. Use one owner per installation. Preserve multiple accounts as a future requirement. Use English web copy and a Go CLI. Use local credentials instead of an external identity provider. Use 24 hours as the initial switch interval and one hour as the initial grace. Use three acknowledgments for renewal as the approved initial design, subject to the protocol review. An unavailable agent can therefore prevent renewal. The owner approved this tradeoff on 2026-11-04. Use bounded clock error as a protocol prerequisite. The review establishes the supported bound. Use a 10 MiB content limit and owner-controlled retention. Keep provider selection and actual infrastructure cost outside this planning decision.

Risks & open questions

Review decisions

  • The owner accepts the bounded receipt-loss tradeoff on 2026-11-05. Clock and publication allowances remain protocol-review outputs.
  • The owner approved three-agent renewal and its availability tradeoff on 2026-11-04.
  • The owner approved the scaffold proposal on 2026-11-04.
  • The owner accepted server exposure during v1 web preparation on 2026-11-04.

Technical gates

  • Incomplete receipts create uncertainty from B0 through Bmax, plus E. The owner accepts almost 24 hours under the default interval.
  • B0 does not prove actual authority after receipt loss. A missing response can hide a fully accepted renewal.
  • The revised model must verify Bmax plus E after main loss and one outage with two reachable, honest, durable agents.
  • Permanent client loss, retry journals, delayed requests, and irreversible observer history remain protocol-review obligations.
  • Published shares can survive later renewals. The protocol must account for their cumulative disclosure.
  • Two colluding agents can disclose a secret early. V1 does not cover this attack.
  • Agent clock error can cause early or late release. The protocol review defines a measured bound and an unsafe-clock response.
  • A lost signing key can prevent renewal. Export and recovery procedures must state this consequence.
  • The DNS adapter passes synthetic compatibility checks. Production integration and public delegation remain separate gates.
  • The tlock adapter requires an explicit verified network configuration and version check.
  • The maintained store, threshold library, password library, and lint tools require pinned documentation before code uses them.
  • The reference deployment needs independent endpoints and storage, not only three containers on one VPS.
  • External networks can stop. Fixed capsules depend on beacon continuity; renewable external release remains research.
  • A public repository exposes specs and issues. Never place real secrets or host credentials in it.

No unanswered product question blocks the approved plan. Technical gates block the affected implementation or production claim.
